## wrap.py 改动最小化规则

这份规则专门用于 `headroom/cli/wrap.py` 下的改动，尤其是代理相关行为的新增、调整和收缩。

### 1. 优先使用环境变量，不优先走参数透传

- 使用 `HEADROOM_REMOTE_PROXY_URL` 作为远端代理模式的唯一事实来源（判定入口）。
- 不要把 `HEADROOM_PROXY_URL` 当作模式判定的输入：它是「客户端/插件往哪里发请求」的下游路由变量，会被写进子进程环境，拿它做判定会让嵌套 wrap 误判成远端模式。
- 远端模式下 `HEADROOM_PROXY_URL` 的**值**仍然应该是远端地址，统一由 `resolve_proxy_root()` 解析：配置了远端就用远端 URL，否则回落本地 `http://127.0.0.1:{port}`。
- 优先让 helper 在内部读取这个环境变量。
- 除非没有安全替代方案，否则不要为了远端代理一路新增或传递 `proxy_url` 参数。

### 2. 在方法内部拦截，不在外层调用点分叉

- 优先在 `_ensure_proxy()` 这类共享 helper 里做内部拦截。
- 不要在 `claude()`、`codex()`、`cursor()`、`opencode()` 这类顶层命令里新增大块 `if/else` 分支，只为区分本地代理和远端代理。

### 3. 控制流尽量贴近 `origin/main`

- 能保留原有执行顺序就保留原有执行顺序。
- 不要用新的条件分支包住大块已有代码，除非没有更小的实现方式。
- 优先选择一条小 guard、一个局部替换，或者一次内部拦截，而不是整体搬动、重排、重缩进已有逻辑。

### 4. 避免 helper 膨胀和抽象漂移

- 不要新增 helper，除非它带来的 diff 缩减大于它本身引入的改动。
- 如果 helper 可以在内部读取现有环境状态，就不要扩展它的函数签名。
- 如果某个桥接 helper 只是为了当前分支临时存在，后续应优先删除，而不是长期保留额外抽象。

### 5. 行为改动时禁止顺手格式化

- 除非为正确性所必需，否则不要顺手改附近代码的换行、缩进、顺序或风格。
- 不要把“整理代码样式”混进代理行为改动里。
- patch 必须保持外科手术式最小化，尽量减少以后 rebase 和 merge 时的冲突行数。

### 6. 把 remote-proxy 支持视为兼容性工作，而不是重设计

- 核心目标是：在 **没有** `HEADROOM_REMOTE_PROXY_URL` 时，保留原有本地代理行为。
- 远端代理模式必须是增量式、低风险的。
- 如果某个改动让代码更“漂亮”，但明显增加了分支漂移，就不应该保留。

### 7. 用聚焦回归测试验证，而不是靠主观判断

- 每次缩 diff 之后，都要重跑针对 env-only remote-proxy 的聚焦测试。
- 至少覆盖下面这些行为：
  - 远端 URL 解析是否正确；
  - MCP / retrieve 是否仍然指向正确代理；
  - OpenCode `prepare-only` 配置是否正确写入；
  - Claude 远端模式下是否不会误写本地 self-heal 端口；
  - Codex 自定义 upstream 处理是否仍然正确。

### 8. 每保留一处改动前都问自己一次

在决定保留 `wrap.py` 里的某个改动前，先问：

> 这段行为，能不能通过“使用环境状态 + 更低层拦截”的方式，用更少的改动行数实现？

如果答案是可以，就优先选择改动更小的版本。
